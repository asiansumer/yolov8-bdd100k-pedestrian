# P1 复习笔记：精读 evaluate_by_group.py

2026-10-18。这个脚本产出分组评估表 `reports/eval_<实验名>/group_metrics.csv` 和 `.md`。

## 两种分组，两种算法

| | 场景分组（时间、天气、拥挤） | 大小分组（small/medium/large） |
|---|---|---|
| 是谁的属性 | 整张图 | 每个人（一张图里大小混着） |
| 怎么算 | 按图分堆，交给 Ultralytics 的 `model.val()` | 自己写的 `match_image` + `size_ap` |
| 好处/代价 | 和整体 mAP 同一套算法，可以直接比 | 官方不支持按大小拆；全点插值，和官方数值不完全可比，报告里注明了 |

## 按代码顺序

1. **读元数据**：`csv.DictReader` 把每行变成字典。CSV 读出来全是字符串，比较前要 `int(r["num_ped"])`（`"12" >= 10` 报错；`"9" >= "10"` 是 True）。
2. **派生拥挤**：行人数 ≥ `args.crowd_threshold`（默认 10）算 crowded。门槛做成参数，改的时候不用动代码。
3. **场景分堆**：`for key in (...)` 每圈新建 `groups = defaultdict(list)`，每圈只装一种属性。`defaultdict(list)` 查不存在的钥匙会自动放一个 `[]`。
4. **每堆算 mAP**：少于 `--min-images`（20）张跳过；文件名里的空格和 `/` 换成 `_`；路径写进 txt + yaml，交给 `model.val()`。
5. **大小分组**：
   - `conf=0.001`：小目标的 conf 往往很低，门槛高了会把它们的 TP 提前扔掉，P-R 曲线提前断，AP 被低估，小目标最严重。门槛是部署时才选的。
   - 用 `Path(r.path).stem` 找标签（`b7c2.jpg` → `b7c2.txt`）：Ultralytics 会打乱顺序，按位置对会拿 A 图的框对 B 图的人。这种错不报错，只是 AP 很低，属于“安静的 bug”。
   - 所有图的 records 和真人数攒起来，最后一起算 AP。
   - 图片列表写成 txt 再交给 predict：直接传 1 万张图的列表会同时打开太多文件。
6. **写表**：每行一个字典，`{..., **run_val(...)}` 把小字典倒进大字典（结果是一个字典）。写 csv 给程序读，写 md 给 README 用。

## 读结果时要小心

- `timeofday=undefined` 只有 35 张图、7 个人，mAP50 0.87 不能说明模型在这里最好：样本太少（投 2 中 2 不代表比投 100 中 70 准）。
- 局限：门槛按图片数（20 张）设，更严谨的是按人数设。

## 面试自测（我的回答要点）

1. 为什么场景用官方 val、大小自己算？ → 天气是图的属性能分堆，用官方保证和整体可比；大小是人的属性没法按图分，官方也不按大小拆，只能自己写，并注明不完全可比。
2. 为什么 conf=0.001？ → 远处小人 conf 低但确实被认出来了，门槛高会被扔掉；AP 要评价所有门槛，提前砍会让曲线断掉、AP 被低估。
3. 为什么用 r.path？ → 预测顺序会被打乱，按位置对会错配；而且不报错，只会让 AP 莫名变低。
4. 模型最大的问题、怎么改？ → 小目标 AP50 只有 0.41（大目标 0.93），远处行人认得差，对刹车距离是安全隐患。改进：提高输入分辨率（640 → 1280）、切图推理、加小目标检测头、增加小目标样本。
