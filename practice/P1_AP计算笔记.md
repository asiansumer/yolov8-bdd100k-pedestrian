# P1 复习笔记：自己实现按大小分组的 AP50

2026-10-17。代码在 `practice/my_size_ap.py`，25 个测试全过，在 300 张随机图上和原版 `scripts/size_ap.py` 结果一致。

整条链：`iou` → `match_image` → `pr_points` → `precision_envelope` → `area_under_pr` → `average_precision` → `size_ap`

---

## 1. iou：两个框重叠多少

- 框是 `(x1, y1, x2, y2)`：`[0][1]` 是起点，`[2][3]` 是终点。
- 交集：起点取 max，终点取 min。类比约开会：最晚到的人到了才开始，最早走的人走了就结束。
- 宽、高分别 `max(..., 0)`，不重叠时不能是负数。
- 并集 = A + B − 交集（交集被加了两次）。并集为 0 直接返回 0.0。
- 为什么除以并集：只看交集的话大框天然占便宜，除以并集变成 0~1 的比例，大小框同一个标准。

踩过的坑：
- 交集元组的 max/min 顺序写乱了，应该是 `(max, max, min, min)`。
- 宽写成 `inter[1] - inter[0]`，应该是 `inter[2] - inter[0]`（终点 − 起点）。

## 2. match_image：一张图里谁配谁

- 预测框按 conf 从高到低处理。
- 每个预测框，在还没被认领的真人里找 IoU 最大的；≥ 0.5 算 TP 并标记 `used`，否则 FP。
- TP 的大小看它配上的真人，FP 的大小看预测框自己 `p[:4]`。
- 没被配上的真人是 FN，不进 records，但它算在 `n_gt` 里，会拉低 recall。
- `p[4]` 是 conf，`p[:4]` 是前 4 个数（坐标）。

踩过的坑：
- `best_j = -1, best_v = 0` 要在每个预测框开头重新初始化。`best_j = -1` 表示还没找到。
- `if best_v >= iou_thr` 那段要放在内层循环外面（找完所有真人才判断），之前缩进进了内层。
- `used` 的长度按真人数开，不是按预测框数。
- 下标从 0 开始数。
- `if used[j]: continue` 跳过已被认领的真人。

为什么：
- 一个真人只能配一次：不然对同一个人输出 5 个框就能刷 5 个 TP。
- 高分先挑：低分的重复框可能抢走真人，把高分的好框变成 FP。
- 找 IoU 最大的而不是第一个 ≥ 0.5 的：两人挨得近时，选错会抢走别人的真人。

## 3. pr_points：P-R 曲线上的点

- precision = tp / (tp + fp)：模型说“有人”时，对了多少。
- recall = tp / n_gt：所有的人里，找到了多少。
- 按 conf 从高到低一个一个接受，每接受一个记一次 (recall, precision)。等价于阈值慢慢放低。

踩过的坑：
- `tp / tp + fp` 漏括号，按优先级算成了 `1 + fp`。要写 `tp / (tp + fp)`。
- precision 的分母是“已经接受的框”，不是全部框。

语法：
- `sorted(records, key=lambda r: r[0], reverse=True)`：`r` 是每一条记录的临时名字，按 `r[0]`（conf）从大到小排。
- `for _, is_tp in ...`：拆包，`_` 表示这个值用不到。

## 4. precision_envelope：精度包络

- 每个点换成“它自己和右边所有点里的最大值”。
- 为什么取右边最大：类比租房“至少 2 卧”。在至少达到这个 recall 的前提下，能拿到的最好 precision 才是模型的真实能力。
- 从右往左走：`range(len(p) - 2, -1, -1)`，`out[i] = max(out[i], out[i+1])`。
- 先 `out = list(precisions)` 复制一份，不改原列表。
- 例子：`[1, 0.5, 0.67, 0.5, 0.6]` → `[1, 0.67, 0.67, 0.6, 0.6]`

## 5. area_under_pr：曲线下面积

- 面积 = Σ (这一点的 recall − 上一点的 recall) × precision。
- FP 处 recall 不变，宽为 0，不加面积。
- 讲义例子：AP = 0.25×1 + 0.25×0.67 + 0.25×0.6 ≈ 0.567。

踩过的坑：写成 `ap = ...`，每次都被覆盖。要累加 `ap += ...`。

## 6. average_precision：组装

- 先处理特殊情况：`n_gt == 0` → `(None, None)`（这组没人，AP 没意义）；没有预测 → `(0.0, 0.0)`。
- 正常情况：`pr_points` → `precision_envelope` → `area_under_pr`。
- 最大召回率 = `recalls[-1]`，因为 recall 只增不减，最后一个最大。
- 函数返回两个值，接收时 `a, b = f(...)`。

## 7. size_ap：按小/中/大汇总

- 外层 `for s in SIZES`，内层挑出 `size == s` 的记录，只留 `(conf, is_tp)`，交给 `average_precision`。
- 每组的 `n_gt` 用 `total_gt[s]`。

踩过的坑：
- 写成了 `total_gt[size]`。内层循环跑完后 `size` 停在最后一条记录（比如 large），算 medium 时拿到了 large 的人数，结果返回 0.0 而不是 None。
- `recs.append((conf, is_tp))` 要两层括号，里面那层是元组。
- 缩进决定一行属于哪层循环：`ap, rec = ...` 和 `out[s] = ...` 在外层循环里、内层循环外；`return out` 在两层循环外。

## Python 小抄

- 缩进 4 格（VS Code 右下角 `Spaces: 2` 点开改成 4）。
- 下标从 0 开始；`p[:4]` 是前 4 个，`p[4]` 是第 5 个。
- 先乘除后加减，不确定就加括号。
- 字典计数：`d[k] += 1`。
- `enumerate` 同时拿下标和值；`zip` 同时走两个列表。
- `+=` 是累加，`=` 是覆盖。

## 面试自测

1. IoU 为什么除以并集？ → 大小框用同一个比例标准。
2. 为什么一个真人只能配一次？ → 防止重复框刷 TP，否则 AP 虚高。
3. 为什么高 conf 先挑？ → 和算 AP 时“按 conf 逐个接受”的顺序一致，避免低分重复框抢走真人。
4. 为什么所有图片合在一起排序？ → 置信度阈值是对整个数据集统一设的。
5. 精度包络在做什么？ → 见第 4 关。
6. 为什么和 Ultralytics 的 AP50 对不上？ → 插值方式不同，我们用全点插值，COCO 用 101 点。
7. FP 为什么按预测框大小分组？ → 误检没有对应的真人，只能看它自己。
8. AP50 和 AP50-95 的区别？ → 后者是 IoU 阈值从 0.5 到 0.95 的平均。小目标偏几个像素 IoU 就掉很多，所以在 AP50-95 上掉得更厉害。
