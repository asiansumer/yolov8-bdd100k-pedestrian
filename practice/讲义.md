## 1. 我们到底要回答什么问题

P1 训练出了三个模型。README 里有一个结论：“小目标是最大短板（AP50 0.41–0.48 vs 大目标 0.93–0.95）”。这一节要搞懂的，就是这几个数字是怎么算出来的。

为什么不直接用 Ultralytics 给的 mAP？因为它只给一个总数。一个总数掩盖了“模型在哪种行人上差”。自动驾驶里，远处的小行人恰恰最危险（看到得晚），所以要单独拿出来看。

要算出“小目标的 AP50”，需要依次解决四个问题：

1. 怎么判断一个预测框“框对了”？→ IoU（第 2 节）
2. 一张图里有多个预测、多个真值，谁和谁算一对？→ 贪心匹配（第 3 节）
3. 怎么用一个数衡量“框得准又框得全”？→ Precision、Recall、P-R 曲线、AP（第 4–7 节）
4. 怎么拆成小/中/大三组？→ 分组规则（第 7 节末尾）

## 2. IoU：两个框重叠了多少

**问题**：模型预测的框几乎不可能和人工标注的框一模一样，差几个像素很正常。所以要有一个“够不够接近”的量化标准。

**定义**：IoU = 交集面积 ÷ 并集面积。

```
  ┌────────┐
  │   A  ┌─┼──────┐
  │      │▒│      │     ▒ = 交集
  └──────┼─┘  B   │     并集 = A 的面积 + B 的面积 − 交集
         └────────┘
```

**为什么是“除以并集”，而不是直接看交集面积？**
如果只看交集，大框天然占便宜：两个 200×200 的框错开一点，交集也有几万像素；两个 10×10 的框完全重合，交集才 100。除以并集之后变成 0 到 1 之间的比例，大框小框可以用同一个标准比较。

**为什么并集要减一次交集？** 面积A + 面积B 时，中间重叠那一块被加了两次。

**交集矩形怎么求？** 框用 `(x1, y1, x2, y2)` 表示（左上角、右下角）。交集的：

- 左边界 = 两个框左边界中**更靠右**的那个，也就是 `max(a.x1, b.x1)`
- 右边界 = 两个框右边界中**更靠左**的那个，也就是 `min(a.x2, b.x2)`
- 上下同理

如果两个框根本不重叠，算出来的“右边界 − 左边界”是负数。负的宽度没有意义，要当成 0。注意可能出现“x 方向重叠、y 方向不重叠”的情况，所以宽和高要**分别**截到 0，而不是只检查一个（测试里专门有一条测这个）。

**AP50 的“50”** 就是：IoU ≥ 0.5 才算框对了。

---

## 3. 匹配：谁和谁算一对

一张图里有若干预测框（每个带一个置信度 conf）和若干真值框。规则：

1. 预测框按 **conf 从高到低** 处理；
2. 每个预测框，在**还没被占用**的真值里，找 IoU 最大的那个；
3. 如果最大 IoU ≥ 0.5，配对成功，这个预测记为 **TP**（True Positive，真阳性），这个真值标记为已占用；
4. 否则这个预测记为 **FP**（False Positive，误检）；
5. 最后没被任何预测配上的真值，就是 **FN**（漏检）。FN 不会出现在记录里，但它会让 recall 变低（第 4 节）。

**为什么一个真值只能被配一次？**
否则模型对同一个人输出 5 个几乎重合的框，就能拿到 5 个 TP，这是作弊。现实中这类重复框本应被 NMS（非极大值抑制）去掉；没去掉的，就该算 FP 惩罚。

**为什么高置信度的先挑？**
因为后面算 AP 也是按置信度从高到低“逐个接受”预测的。高分预测是模型更有把握的，让它优先占用真值，和后面的计算逻辑保持一致。如果顺序反过来，一个低分重复框可能抢走真值，把高分的好框变成 FP，结果就不合理了。

**为什么要找“IoU 最大”的，而不是第一个 ≥ 0.5 的？**
两个行人挨得很近时，一个预测可能和两个人都重叠超过 0.5。选最大的，才是它真正想框的那个人；随便选第一个，可能抢走别人的真值，让另一个本来能配上的预测变成 FP。测试 `test_level2_picks_highest_iou_gt` 就是专门构造的这种情况。

## 4. Precision 和 Recall

假设我们接受了一部分预测（比如 conf ≥ 某个阈值的那些）：

- **Precision（精确率）** = TP ÷ 接受的预测总数 = TP ÷ (TP + FP)
  意思是：模型说“这有人”的时候，有多大比例真的有人。
- **Recall（召回率）** = TP ÷ 真值总数
  意思是：路上所有的人，模型找到了多大比例。

**为什么必须两个一起看？** 只看其中一个，很容易作弊：

- 只看 recall：模型在整张图上铺满框，所有人都被框到，recall = 1，但几乎全是误检。
- 只看 precision：模型只输出它最有把握的那 1 个框，precision = 1，但漏掉了几乎所有人。

对自动驾驶来说：precision 低意味着幻觉刹车，recall 低意味着撞人。两个都不能差。

---

## 5. 置信度阈值和 P-R 曲线

precision 和 recall 都取决于“接受哪些预测”，也就是置信度阈值：

- 阈值设高 → 只接受很有把握的 → precision 高、recall 低
- 阈值设低 → 接受很多 → recall 高、precision 往往下降

部署时阈值可以随便选，所以只报某一个阈值下的数字不公平。做法是：**把阈值从高往低移，每多接受一个预测，就记录一次 (recall, precision)**。这些点连起来就是 P-R 曲线。

实际写代码时不需要真的设阈值：把所有预测按 conf 从高到低排好，从头往后一个一个“接受”，同时累加 TP 和 FP 的计数，就等价于阈值在逐步降低。

注意：要把**所有图片**的记录合在一起排序，而不是每张图单独算。因为阈值是对整个数据集统一设的。

---

## 6. 精度包络：为什么要“从右往左取最大值”

原始的 P-R 曲线是锯齿状的：每遇到一个 FP，precision 往下掉；每遇到一个 TP，又往上回升一点。

包络的做法：每个点的 precision，换成“它自己以及它右边（recall 更大的方向）所有点里的最大值”。

**为什么这样做合理？** 想象你在 recall = 0.25 这个位置，precision 是 0.5。但如果你把阈值再放低一点，能到 recall = 0.5、precision = 0.67 的点，那你在 recall 和 precision 上**都**更好了，没有理由停在 0.25 那里。所以“在至少达到这个 recall 的前提下，能拿到的最高 precision”才是这个模型真实的能力。这样处理后曲线单调不增，面积也不受锯齿抖动影响。

---

## 7. AP = P-R 曲线下的面积

**为什么用面积？** 面积把所有阈值下的表现合成一个数，不需要事先挑阈值。完美模型的曲线是一个 1×1 的正方形，面积 = 1。

**怎么算？** 曲线在 recall 方向上被切成一个个竖长条：

- 宽 = 这一点的 recall − 上一点的 recall（第一点的上一点按 recall = 0 算）
- 高 = 这一点的 precision（包络之后的）
- 面积 = 所有长条的“宽 × 高”加起来

遇到 FP 时 recall 不变，宽是 0，这一条不贡献面积。所以面积只在每个 TP 处增加，增加多少取决于那时的 precision。这叫“全点插值”。COCO 用的是 101 点插值，Ultralytics 有自己的做法，所以数值会有很小的差别（这正是原文件开头“局限性”里说的）。

**最大召回率** 就是 recalls 列表的最后一个值，因为 recall 只增不减，接受完所有预测时最大。它告诉你“就算阈值放到最低，也只能找到这么多比例的人”。

**分组规则（小/中/大）**：

- 面积按 COCO 的阈值：< 32² 像素为小，< 96² 为中，其余为大；
- **TP 归入它配上的真值框的大小组**：因为我们关心的是“这个大小的人被找到了没有”；
- **FP 归入预测框自己的大小组**：误检没有对应的真值，只能看它自己有多大；
- 每组的真值数单独统计，作为这组 recall 的分母。

一个细节：匹配是在所有大小一起做完以后才分组的，所以一个小真值可能被一个偏大的预测配上。这和 COCO 的做法接近，但不完全一样。
